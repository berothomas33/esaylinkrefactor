### The design today (shape 4)

- `PosTerminal` owns the transaction: one single-thread executor runs `transaction::run`; busy =
  `AtomicReference<Transaction> current` (a second start throws `TerminalBusyException` at once).
- `PosTerminal.Transaction`: `config`, `volatile end` (written only under the lock), its own
  `ReplaySubject` steps (also the lock). `steps()`, `cancel()` (CANCELLING now, CANCELLED as the
  end), `isRunning()`, `isCancelled()`, `publish(event)` (an end event ends it), `run()` (the
  attempt loop; a retry is the next turn), `attempt()`, `EngineReportingListener`. The end is
  published once, after the terminal is free.
- `EmvEngine(authorizer)`: `emvSteps` (the dispatch bus), APDU trace, retry, `authorize`. Knows
  nothing of the transaction. Created by `PosTerminal`, handed once with
  `behavior.attach(engine)`, kept only in the behavior; `PosTerminal` reaches it via
  `behavior.engine()`.
- `EmvBehavior`: `attach`, `engine`, `prepare(config, transaction)`,
  `start(config, card, transaction)`, `dispose`. `AbstractEmvBehavior`: `goToStep` (the one cancel
  check), `askStep` / `answerStep` (fail-closed), `publish(event)`, `isRunning()`, `isCancelled()`,
  `finishApproved/Declined(String | event)`, `finishError`, 16 protected `onXxx(config[, card])`.
- **Dispatch (do not touch without a decision):** `EmvStepObserver` subscribes to `emvSteps`, is
  re-subscribed at every prepare/start to stay the last subscriber, and runs the step method
  inside `onNext`.
- Vendors are modules (`:vendor-pax`, `:vendor-fake`, `:vendor-ingenico`); same-FQN
  `TerminalFactory` / `VendorApplication`; screens live in `app/src/main`; vendor data through the
  `PosTerminal` seam (`serialNumber`, `requiredPermissions`, `countries` / `setCountry`,
  `emvParams`).

## 5. Next: EasyLink as an EMV SDK (single tap) — agreed direction, not started

**Goal:** the app becomes an EMV runner. Another app on the terminal starts the transaction; this
app runs EMV (PIN pad, app selection, kernel stay here) and stops at the online point; the outside
app talks to the host and answers.

### 5.1 API

```
outside → SDK:  start(amount, type, ref)   complete(id, hostAnswer)   terminate(id)
SDK → outside:  onOnlineRequest(id, field55, pinBlock, …)   onResult(id, APPROVED | DECLINED | FAILED | CANCELLED, data)
```

- **Single tap:** contactless — `complete` ends from the host answer, no second card presentment;
  chip — the card is still in, `complete` runs the 2nd GAC, then the result.
- `terminate` after `onOnlineRequest` → FAILED / CANCELLED; reversal is the outside's (it talked to
  the host). After `onOnlineRequest` there is no internal cancel: the outside has the last word.
  That closes risk #1 by contract.

### 5.2 How (adapter, no EMV / dispatch change)

- `start` = `terminal.startTransaction(config)`; `terminate` = `transaction.cancel()`.
- `ExternalHost implements CommunicationBehavior` (~40 lines): `authorize(config)` sends the
  request out (`onOnlineRequest`) and returns a `Single` completed by `complete(id, hostAnswer)`.
  The kernel already blocks in `PosTerminal.authorize`; no answer within the timeout = online
  failed (fail-closed, as today). `PaxTerminal` takes the host behavior as a constructor argument.
- `onResult` = the Transaction's end step.
- Transport: bound Service + AIDL in the app (~150 lines): `IEmvService` / `IEmvCallback`.
- Removed (your call): the steps text in `SearchCardFragment`, the `emvSteps` banner in
  `MainViewModel`. **Kept:** the dispatch, and the behavior's `publish(...)` (the result and the
  trace are built from them; removing them = ~19 vendor edits for nothing).
